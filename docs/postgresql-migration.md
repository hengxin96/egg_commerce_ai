# PostgreSQL + pgvector Local Setup

## 1. Start PostgreSQL With pgvector

Open Docker Desktop first, then run from the project root:

```powershell
cd D:\Code_Workspace\egg_commerce_ai
docker compose -f compose.postgres.yml up -d
```

Check status:

```powershell
docker compose -f compose.postgres.yml ps
```

Verify pgvector:

```powershell
docker exec egg-postgres psql -U egg -d egg -c "SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';"
```

Local connection:

```text
Host: localhost
Port: 5432
Database: egg
Username: egg
Password: egg_dev_password
JDBC URL: jdbc:postgresql://localhost:5432/egg
```

## 2. Navicat Migration From MySQL

The project now includes a converted PostgreSQL initialization script:

```text
sql/egg_postgresql.sql
```

It was generated from the original MySQL script and has already been imported into the local Docker PostgreSQL database.

To re-import it manually:

```powershell
docker cp .\sql\egg_postgresql.sql egg-postgres:/tmp/egg_postgresql.sql
docker exec egg-postgres psql -v ON_ERROR_STOP=1 -U egg -d egg -f /tmp/egg_postgresql.sql
```

Recommended Navicat path if you have existing local MySQL data:

1. Create a PostgreSQL connection in Navicat with the connection info above.
2. Open the PostgreSQL `egg` database.
3. Import `sql/egg_postgresql.sql` first to create a PostgreSQL-compatible schema.
4. Use Navicat's data transfer tool to move data from MySQL into the existing PostgreSQL tables.
5. For tables with existing default data, choose overwrite/truncate carefully to avoid duplicate primary keys.
6. After migration, check primary keys, indexes, and identity sequences.
7. Run smoke tests: login, menu loading, user list, role list, dict list, config list, scheduled job list.

Common MySQL-to-PostgreSQL adjustments:

```text
auto_increment       -> generated by default as identity / sequence
datetime             -> timestamp
longtext             -> text
bit(1)               -> boolean or smallint
tinyint              -> smallint
ifnull(a, b)         -> coalesce(a, b)
sysdate()            -> now()
date_format(x, fmt)  -> to_char(x, fmt)
find_in_set(x, col)  -> x = any(string_to_array(col, ',')::bigint[])
`query`              -> "query" or query if not quoted
ENGINE/CHARSET       -> remove
```

## 3. Backend Configuration

The project has been switched to PostgreSQL:

- `egg-admin/pom.xml` uses `org.postgresql:postgresql`
- `application-druid.yml` defaults to `jdbc:postgresql://localhost:5432/egg`
- `application.yml` uses `pagehelper.helperDialect: postgresql`
- Key MyBatis mapper SQL under `egg-system` and `egg-quartz` has been adapted from MySQL syntax to PostgreSQL syntax.
- `egg-framework` data-scope SQL has been adapted away from MySQL `find_in_set`.

Redis currently maps Docker host port `6380` to container port `6379`, so the backend default Redis port is set to `6380`.

## 4. Run The Backend

From the project root:

```powershell
mvn -q -pl egg-admin -am package -DskipTests
java -Dserver.port=18080 -jar .\egg-admin\target\egg-admin.jar
```

If PowerShell mis-parses `-Dserver.port=18080`, use:

```powershell
java @('-Dserver.port=18080','-jar','.\egg-admin\target\egg-admin.jar')
```

Startup is successful when the console prints:

```text
Started EggApplication
Egg启动成功
```

## 5. Remaining Limitation

The base backend has been verified to start with PostgreSQL. The remaining known PostgreSQL adaptation risk is the code generator module:

- Generator metadata queries under `egg-generator`

If the code generator page fails while importing database tables, adapt the generator metadata queries to PostgreSQL `information_schema` / `pg_catalog`.
